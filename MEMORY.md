- 2026-10-05 [art] Eye-tracking bug root causes: (1) look direction came from the head centre (`stage.head`, fixed box y=28) through `tanh(d/55 logical px)`, so near the face it was ~linear but tiny and then (2) quantised to 0.25 with `Math.round`, which is asymmetric (`round(-0.5) = -0`, `round(0.5) = 1`): a dead zone for leftward/upward looks and a 1px bias rightward; the kit's `Math.round(lookX*2)` had the same asymmetry; (3) both eyes shared one direction (no convergence) so a cursor over one eye or between the eyes looked wrong; (4) the look spring (k 420, c 36, underdamped, ~200 ms) lagged at 12 fps; (5) the peek rotation was ignored. Fix: pure `behavior/look.ts computeLook(sample, eyes)` per eye from window bounds + eye stage position x (winW/STAGE_W), undoing peek rotation, mapped with `d/sqrt(d^2+D^2)` (D = 1.5 x eye radius: proportional near, saturating far) + a small convergence bonus between the eyes; PoseState.eyes.conv (left = lookX+conv, right = lookX-conv); symmetric `q()`/`sround()`; springs critically damped k 1600 c 80 (~25 ms); sclera irises clipped to the eye white. Units: CursorSample x/y and win bounds must share one unit (DIP or physical) - only the ratio matters (tests cover scale 1-4 x DPR 1-2). Tauri port: keep cursor + window bounds in the same unit.
